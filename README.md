# Приёмная комиссия — C# WPF (MVVM) + PostgreSQL

Вариант 2. Абитуриент регистрируется на один из факультетов с фиксированным планом набора
и вводит баллы по предметам и аттестату. Администратор регистрирует результаты в ведомости.
Система считает сумму баллов и определяет зачисленных абитуриентов.

## Что нужно установить

| Программа | Зачем |
|---|---|
| **Visual Studio 2022** с нагрузкой «Разработка классических приложений .NET» | открыть и запустить проект (.NET 8, WPF) |
| **PostgreSQL 13+** (https://www.postgresql.org/download/windows/) | сервер БД. При установке запомните пароль пользователя `postgres` |
| **DBeaver** | создать базу, выполнить скрипты, посмотреть ER-диаграмму |

## Шаг 1. База данных в DBeaver

1. **Новое соединение → PostgreSQL**: Host `localhost`, Port `5432`, Database `postgres`,
   Username `postgres`, Password — пароль, заданный при установке PostgreSQL.
2. Создайте базу: ПКМ по **Базы данных → Создать новую базу данных**, имя `admission_committee`
   (или в SQL-редакторе: `CREATE DATABASE admission_committee;`).
3. Выберите базу `admission_committee`, откройте **SQL-редактор** и по очереди откройте и выполните
   скрипты из папки `Database` целиком (**Alt+X** — «Выполнить SQL-скрипт»):
   1. `01_schema.sql` — таблицы, ограничения, триггеры журнала, представления, функции зачисления;
   2. `02_seed.sql` — тестовые данные;
   3. `03_security.sql` — роль `admission_app` с минимальными правами (под ней работает приложение).

   Если вы снова запускаете `01_schema.sql`, после него запустите ещё раз `02` и `03`.
4. ER-диаграмма для курсовой: в навигаторе раскройте `admission_committee → Схемы → public`,
   ПКМ по `public` → **Просмотр диаграммы** (View Diagram). Её можно сохранить как картинку.

## Шаг 2. Приложение в Visual Studio

1. Откройте `AdmissionCommittee.sln`.
2. Нажмите **F5**. При первой сборке Visual Studio сама скачает пакет `Npgsql` (нужен интернет).
3. Строка подключения — в файле `AdmissionCommittee/appsettings.json`. Если вы меняли пароль роли
   в `03_security.sql` или порт PostgreSQL, поправьте его там.

### Тестовые учётные записи

| Логин | Пароль | Роль |
|---|---|---|
| `admin` | `admin123` | Администратор |
| `ivanov`, `petrova`, `sidorov`, `kuznetsova`, `smirnov`, `volkova`, `morozov`, `lebedeva`, `novikov`, `fedorova`, `sokolov`, `popova` | `12345` | Абитуриент |

В тестовых данных специально есть разные случаи: Смирнов набрал по математике меньше минимума,
у Новикова баллы ещё не проверены, у Поповой не введена история, Сидоров и Морозов не проходят по плану.

## Как работает система

1. **Абитуриент** регистрируется: логин, пароль, ФИО, дата рождения, факультет, средний балл аттестата.
2. В личном кабинете вводит баллы (0–100) по предметам своего факультета.
3. **Администратор** на вкладке «Ведомость» проверяет баллы и **регистрирует** их (при необходимости исправив).
   Зарегистрированный балл абитуриент изменить уже не может.
4. **Сумма баллов** = баллы по зарегистрированным предметам факультета + средний балл аттестата × 10.
   К конкурсу допускается абитуриент, у которого по **всем** предметам факультета есть
   зарегистрированный балл не ниже минимального.
5. Рейтинг строится по каждому факультету: сумма ↓, аттестат ↓, дата подачи ↑.
   Первые N (N — план набора) проходят.
6. Кнопка **«Подвести итоги»** вызывает функцию БД `fn_run_enrollment()`: проходящим — «Зачислен»,
   остальным — «Не зачислен». «Отменить итоги» возвращает всем статус «Подано».

Вся логика подсчёта находится в базе (представления `v_applicant_totals` и `v_rating`),
поэтому её можно показать и проверить прямо в DBeaver: `SELECT * FROM v_rating;`

## Структура базы данных

| Таблица | Назначение |
|---|---|
| `roles` | роли: Администратор, Абитуриент |
| `users` | учётные записи, пароль хранится только как хэш PBKDF2-SHA256 |
| `faculties` | факультеты, `plan_count` — план набора |
| `subjects` | предметы (вступительные испытания), `min_score` — минимальный балл |
| `faculty_subjects` | какие предметы сдаются на какой факультет (связь M:N) |
| `applicants` | абитуриенты: факультет, аттестат, статус заявления |
| `statement_entries` | **ведомость**: балл по предмету, зарегистрирован ли, кем и когда |
| `audit_log` | журнал изменений (заполняется триггерами) |

Связи: `roles 1—N users`, `users 1—1 applicants`, `faculties 1—N applicants`,
`faculties N—M subjects` (через `faculty_subjects`), `applicants 1—N statement_entries`,
`subjects 1—N statement_entries`.

## Архитектура приложения (MVVM)

```
AdmissionCommittee/
├── Models/           классы данных: Faculty, Subject, Applicant, StatementRow, RatingRow ...
├── ViewModels/       логика экранов: Login, Register, ApplicantCabinet, Admin + вкладки
├── Views/            XAML-разметка экранов (UserControl), код-behind пустой
├── Infrastructure/   ViewModelBase (INotifyPropertyChanged), RelayCommand,
│                     AsyncRelayCommand, PasswordHelper (привязка PasswordBox)
├── Data/             Database (подключение), репозитории с SQL-запросами, DbErrors
├── Services/         PasswordHasher, DialogService, AppConfig, AppServices
├── App.xaml          стили и DataTemplate «ViewModel → View»
└── MainWindow.xaml   шапка + ContentControl, показывающий текущий экран
```

- View не содержит логики: всё через `Binding` и `ICommand`.
- ViewModel не знает о кнопках и окнах: сообщения показываются через интерфейс `IDialogService`.
- Навигация: `MainViewModel.CurrentView` хранит ViewModel текущего экрана,
  а WPF сам подбирает View по `DataTemplate DataType=...` в `App.xaml`.

## Защита данных

| Угроза | Мера |
|---|---|
| SQL-инъекция | только параметризованные запросы (`@параметры`), ввод проверяется во ViewModel |
| Утечка паролей | PBKDF2-SHA256, 100 000 итераций, случайная соль; сравнение за постоянное время |
| Подбор пароля | после 5 неудачных попыток вход блокируется на 30 секунд |
| Избыточные права | приложение работает под ролью `admission_app`: нет DELETE на `users`, нельзя менять журнал, нельзя создавать таблицы |
| Ошибки ввода | `CHECK` (балл 0–100, аттестат 3–5, план > 0), `NOT NULL`, `UNIQUE`, `FOREIGN KEY` |
| Подмена баллов | зарегистрированный балл абитуриент изменить не может (условие в `ON CONFLICT ... WHERE`) |
| Нет контроля действий | триггеры пишут в `audit_log` каждое изменение ведомости, абитуриентов, факультетов, пользователей (хэш пароля в журнал не попадает) |
| Потеря данных | резервная копия: в DBeaver ПКМ по базе → **Инструменты → Резервное копирование** (pg_dump) |

## Если что-то не работает

| Сообщение | Что сделать |
|---|---|
| «Нет связи с сервером PostgreSQL» | запустите службу PostgreSQL, проверьте порт в `appsettings.json` |
| «неверный пароль в appsettings.json» | выполните `03_security.sql` или исправьте пароль в строке подключения |
| «База данных admission_committee не найдена» | создайте базу (шаг 1.2) |
| «Недостаточно прав» | выполните `03_security.sql` (после каждого повторного запуска `01_schema.sql`) |
| Visual Studio не находит `Npgsql` | ПКМ по решению → «Восстановить пакеты NuGet» |
